# Batch Execution Rules

## Task Selection Criteria

- Must advance core gameplay systems
- Must be meaningful product increments 
- Cannot reopen verified systems unless regression is detected
- Must focus on material advancement:
  * environment
  * Shift interaction  
  * physical architectural transformation
  * route choice
  * risk/reward
  * Flux
  * extraction
  * retry
  * vertical-slice integration

## Task Quality Requirements

- Each task should be self-contained
- Clear acceptance criteria
- Should contribute to playable game experience
- Cannot simply verify existing functionality repeatedly
- Must represent net product advancement rather than just maintenance
